# Fastlane — Google Play release setup

> `README.md` in this folder is auto-generated by fastlane on every run.
> This file (`SETUP.md`) is the hand-written guide — fastlane leaves it alone.

Build a signed release AAB and upload it to Google Play with one command.

```bash
fastlane android release                 # build + upload to production
fastlane android release track:internal  # build + upload to internal testing
fastlane android release rollout:0.1     # staged 10% production rollout
fastlane android upload                  # upload the already-built app-release.aab
fastlane android validate                # check the service-account credentials
```

Signing comes from `keystore.properties` (already wired in `app/build.gradle`).
Play credentials come from `~/.config/etipitaka/play-service-account.json`,
which lives **outside the repo** so the key can never be committed (Google
auto-disables service-account keys found in public repos). Override the path
with the `SUPPLY_JSON_KEY` env var.

## One-time setup

### 1. Service account + key (Google Cloud Console) — DONE

Already created: service account `play-publisher@watnapp.iam.gserviceaccount.com`
in project `watnapp`, key downloaded to
`~/.config/etipitaka/play-service-account.json` (chmod 600).

If you ever need to recreate it:

1. <https://console.cloud.google.com/> → project `watnapp`.
2. **APIs & Services → Library** → enable **Google Play Android Developer API**.
3. **Credentials → Create credentials → Service account** → name `play-publisher`.
4. Service account → **Keys → Add key → Create new key → JSON → Create**.
   The browser downloads the JSON **once** in that dialog — there is no
   re-download. If you lose it, delete the key and create a new one.
5. Move it out of the repo:
   ```bash
   mkdir -p ~/.config/etipitaka
   mv ~/Downloads/watnapp-*.json ~/.config/etipitaka/play-service-account.json
   chmod 600 ~/.config/etipitaka/play-service-account.json
   ```

### 2. Grant the service account access (Play Console) — REQUIRED NEXT

`fastlane android validate` fails with *"Could not establish a connection"*
until this is done. The key file is valid; the service account just has no
permission on the Play account yet.

1. <https://play.google.com/console/> → **Users and permissions** (the
   account-level page in the all-apps view, *not* inside a single app).
2. **Invite new users** → email: `play-publisher@watnapp.iam.gserviceaccount.com`.
3. **App permissions** → add **E-Tipitaka** (`com.watnapp.etipitaka.plus`).
4. **Account permissions** → grant at least:
   - **Releases: Manage production releases** (for the `production` track)
   - **Releases: Manage testing track releases** (for `internal` / `beta`)

   Or, for a personal account, just **Admin (all permissions)**.
5. **Invite user** / **Send invitation**.

Propagation can take a few minutes to a few hours.

### 3. Verify

```bash
fastlane android validate
```

Expect *"Successfully established connection to Google Play Store"*.

## Usage

### Build + upload (default)

```bash
fastlane android release
```

`./gradlew clean bundleRelease` then uploads the fresh signed AAB to the
**production** track, completed rollout. Bump versionCode/versionName in
`app/build.gradle` before releasing — fastlane reads them from the AAB.

### Upload an already-built AAB

```bash
fastlane android upload                 # app/build/outputs/bundle/release/app-release.aab
fastlane android upload aab:path/to.aab
```

### Staged rollout

```bash
fastlane android release rollout:0.1    # 10% of users; release_status = inProgress
```

Bump or complete the rollout later from the Play Console, or re-run with a
higher `rollout:`.

### Other tracks

```bash
fastlane android release track:internal
fastlane android release track:beta
```

## Gotchas

- **First production release must be manual.** Google requires the *very first*
  release of an app on production to go through the Play Console UI. After
  that, the API (fastlane) can publish. This app already has prior production
  releases, so this only matters for a brand-new app.
- **Service-account JSON is secret and lives outside the repo**
  (`~/.config/etipitaka/play-service-account.json`). Not in the project tree,
  so it can't be `git add`-ed by accident. Anyone with it can publish to your
  Play account. Google auto-disables keys found in public repos — if that
  happens or the key leaks, delete it in Cloud Console and create a new one.
- **The JSON downloads only once**, at key creation. No re-download. Lost key →
  delete + recreate.
- **Permission propagation lag.** A freshly invited service account may return
  `403` / connection errors for a while. Wait and retry `validate`.
- **`completed` rollout to production** publishes to all users after Google
  review. Use `rollout:` for a staged release if you want a safety valve.
- **UTF-8 locale warning** from fastlane is harmless. Silence it with
  `export LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8` in your shell profile.
